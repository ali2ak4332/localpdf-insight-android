# Apt Reader development

Status: **implemented development candidate; release blocked by model quality.**
Read [VALIDATION.md](VALIDATION.md) before using this branch. Do not distribute the
internal APK as a validated release. Main remains LocalPDF 0.2.7.

## Design and operation

The reader keeps application ID `app.localpdf.insight`, origin
`https://appassets.androidplatform.net`, IndexedDB `localpdf-android-reader-v1`
and existing local-storage keys. Apt Reader is an in-place update development
branch, not a side-by-side application. No database migration or uninstall is
required. The actual populated-installation upgrade still needs a device test.

Open View options → Analyze PDF. Five functions are available: Summarize,
Extract Insights, Extract Key Figures, Identify Risks & Obligations, and Verify
Findings. The first four ask Gemma to select source passages, then release only
exact source text checked by independent code. This is **extractive analysis**,
not validated abstractive summarization. Verify Findings does not invoke the
model: it rechecks source spans or searches for an exact pasted finding. Text
presence is not proof of meaning, truth or completeness. Paraphrases that cannot
be matched remain unsupported. No numerical arithmetic is generated.

Each extract retains a document/revision/source identity and physical page.
Nearby line sources have separate citations to expose wrapped clauses, exceptions
and table context. Nearby context is bounded and never claimed complete. Page
links reuse the reader's source highlighting, which highlights the indexed source
region, not a precise character selection. Printed page labels can differ.

Existing PDF.js extraction/indexing is reused. Analysis is bounded to 6,000 text
characters/12 source spans per section, 48 sections and 40 released findings by
default. Limits, failed/omitted sections, missing indexed text and processed pages
are disclosed. Pages without selectable text are not analyzed. No OCR, embeddings,
server, Python interpreter, telemetry or HTTP client is added to Android.

## Model setup

Use the pinned [ggml-org Gemma 3 270M instruction-tuned QAT Q4_0 artifact](https://huggingface.co/ggml-org/gemma-3-270m-it-qat-GGUF/resolve/7dba9faa7cdb58c7dc44b238c7dbb00e391fbf65/gemma-3-270m-it-qat-Q4_0.gguf).
This is a conversion published by the runtime maintainers, derived from Google's
model; it is not an Apt Reader fine-tuned model. Review the
[Gemma terms](https://ai.google.dev/gemma/terms).

- Filename: `gemma-3-270m-it-qat-Q4_0.gguf`.
- Exact size: **241,410,624 bytes**.
- SHA-256: `3626e245220ca4a1c5911eb4010b3ecb7bdbf5bc53c79403c21355354d1e2dc6`.

Download outside the reader, then use Model setup → Import model. A private
no-backup copy is imported through the Android document picker. The app checks
the full digest/size, syncs the pending file, and atomically replaces only a valid
model. A failed/cancelled import retains an old model; pending crash files are
cleaned on the next app/controller startup. Replacement temporarily needs space
for both old and new files. The original external download is separate phone
storage. The app itself has no INTERNET permission, including during setup.

Inference uses CPU llama.cpp at commit
`df9beac7153166550571c70cc667f270b745da49`; its source archive SHA-256 is
`35c3811bef57f5e5e3d09cce9b487ca6adeeb6783cdb259712075ee36f38b4e8`.
CMake downloads the pinned dependency at build time only. The code runs one
inference at a time, using a 4,096-token context, at most 4 CPU threads and at most
96 output tokens. Weights are memory-mapped, text context is cleared between
requests, and cancellation is checked during loading/prefill/generation.
The native source contains no HTTP/download dependency. Native JNI is packaged
for arm64-v8a and x86_64. Unsupported native runtime errors leave reading usable.

## Reproduce

Install JDK17, Gradle8.9, Android SDK35/build-tools35.0.0, NDK28.2.13676358,
Android CMake3.22.1 and a current Chromium/Playwright1.62.1 for browser checks.
Model weights and private signing material must stay outside the source tree.
Existing `LOCALPDF_ANDROID_*` signing configuration is preserved; no new key is
generated by the Apt Reader code. The original certificate is recorded in the
validation report.

```sh
node --test tests/apt/*.test.mjs
node tests/apt/panel.cjs
node tests/browser/android.cjs
node tests/browser/android_editor.cjs
node tests/browser/android_reading_tools.cjs
python3 tests/native/pdf_print_policy.py
python3 tests/native/pdf_share_policy.py
python3 tests/native/reading_screen_policy.py
cd android
./gradlew --no-daemon assembleRelease lintRelease
```

`CHROMIUM_EXECUTABLE` can select a current browser. An already checked-out pinned
llama.cpp source may be provided with `-PaptLlamaSource=/absolute/path`; otherwise
the digest-checked CMake download is used. Do not point that override at a different
revision and claim the pinned-runtime results still apply.

Host native tests use the same production engine:

```sh
cmake -S android/app/src/main/cpp -B /tmp/apt-host -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/apt-host --parallel 4
python3 tests/apt/native_smoke.py /tmp/apt-host/apt-select /path/to/model.gguf
/tmp/apt-host/apt-cancel-test /path/to/model.gguf
node tests/apt/model_baseline.mjs /tmp/apt-host/apt-select /path/to/model.gguf /tmp/model-results.json
```

The baseline is a synthetic diagnostic, not the required 30–50 PDF benchmark.
No successful fine-tuning is claimed. Before release, improve and evaluate the
model on rights-cleared, reviewed examples, retain document-disjoint train/test
sets, complete the representative PDF gold corpus, test the exact quantized
artifact, and perform actual Android offline/update/retention/performance tests.
